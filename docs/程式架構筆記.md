## 1. 整體概念

- **目標**：在 bare-metal RV64IMC 上執行 INT8 量化的 DeiT-Tiny，量測瓶頸，再設計自訂指令（packed INT8 MAC、requant）加速
- **期中重點**：ISA 設計與 Spike 上的自訂指令（B0 → B1 → X1 → X2 的指令數比較）
- **期末重點**：把自訂指令做進 CV-Wally RTL，量測 cycle、CPI、面積與 Fmax

### 兩條程式線

| | 完整模型（`runtime/`） | 自己寫的 kernel（`src/`） |
|---|---|---|
| 是什麼 | 用 LiteRT Micro 執行完整 DeiT-Tiny（489 個運算） | 自己寫的 FC、matmul、softmax 等單一 kernel |
| 用途 | **B0 基準、完整模型評估、瓶頸分析** | **微基準**（規格要求的 microbenchmark）、新指令的第一個試驗場 |
| 正確性 | 與 Python LiteRT 輸出逐位元相同 | 與 Python 參考算法逐位元相同 |

### 三個角色

| 角色 | 是什麼 | 在這個專案做什麼 |
|---|---|---|
| **Mac** | 你的電腦 | 存放所有程式碼與結果，用 VS Code 編輯；Python 量化環境 |
| **Docker 容器** | Linux 環境（`rv64-dev`） | 提供工具：RISC-V GCC、Spike、g++、Python |
| **Spike** | RISC-V 指令集模擬器 | 模擬一顆 RV64IMC CPU，程式實際跑在這裡 |

```text
你的 Mac（macOS）
 └─ Docker 容器（Linux）         ← 提供工具
     └─ Spike（模擬的 RV64 CPU）  ← 程式真正執行的地方
```

- 容器裡的 `/work` 就是 Mac 上的「期中project」資料夾（用 `-v` 掛載），不是另一份拷貝

## 3. 模型怎麼來的（離線，在 Mac 的 Python 環境）

`models/deit_tiny_int8.tflite` 是**我們自己量化產生的**（第 ③ 步的輸出），不是下載的。下載的只有 FP32 模型。

```text
① 下載 FP32 模型
     HuggingFace litert-community/deit_tiny_patch16_224 的 model.tflite
     （timm 的 PyTorch DeiT-Tiny 轉成 LiteRT，22,978,000 bytes）
     → 存成 models/deit_tiny_fp32.tflite
          ▼
② 準備圖片：scripts/prepare_imagenette.py
     python3 scripts/prepare_imagenette.py <Imagenette 驗證集 parquet> --calib 20 --eval 100
     → data/imagenette/calib/（每類 20 張，共 200 張，量化校正用）
       data/imagenette/eval/ （每類 100 張，共 1000 張，量準確率用）
          ▼
③ 量化：scripts/quantize_deit.py        ★ deit_tiny_int8.tflite 在這一步產生
     python3 scripts/quantize_deit.py models/deit_tiny_fp32.tflite models/deit_tiny_int8.tflite --calib 200
     a. 修 FP32 模型（不改變計算結果，並確認輸出與原本完全相同）
        ・重複的 tensor 名稱加編號（量化工具要求名稱唯一）
        ・36 個 SQUEEZE → 等價的 RESHAPE（量化工具不支援 INT8 SQUEEZE，否則會留成浮點）
     b. 校正：200 張圖跑過 FP32 模型，記錄每個 activation 的最小 / 最大值
        → 算出每個 activation tensor 的 scale、zero-point（INT8）
     c. 量化：AI Edge Quantizer，recipe static_wi8_ai8
        ・權重：每個輸出通道各一個 scale（per-channel），存成 INT8
        ・bias：INT32，scale = 輸入 scale × 權重 scale
        ・每個運算換成 INT8 版本（FC、BMM、ADD、SOFTMAX、GELU…）
     d. 權重從檔案尾端搬回 flatbuffer 內部（LiteRT Micro 讀不到放在檔尾的權重）
     → 輸出 models/deit_tiny_int8.tflite（6.4 MB，489 個運算）
          ▼
④ scripts/check_no_float.py models/deit_tiny_int8.tflite
     檢查每個運算的輸入輸出都不是浮點 → 489 個運算 PASS
⑤ scripts/eval_tflite.py models/deit_tiny_int8.tflite
     1000 張的 top-1 / top-5（電腦版 LiteRT）→ results/accuracy.txt
⑥ scripts/make_runtime_io.py models/deit_tiny_int8.tflite runtime/build/io
     取 1 張評估圖量化成 INT8 輸入（input.bin），用電腦版 LiteRT 參考 kernel
     算出正確輸出（golden.bin）→ RISC-V 端拿來逐位元比對（也可用 runtime 的 make io）
```

## 4. 模型怎麼串接、怎麼執行（`runtime/`）

### 模型檔本身就是運算清單

`.tflite` 裡有 tensor 清單（形狀、INT8 量化參數、權重）和**照執行順序排好的 489 個運算**，每個運算記錄輸入、輸出的 tensor 編號。前一個運算的輸出 tensor 就是下一個的輸入，串接靠的是這些編號，不用自己寫。

```text
[0–9]     Patch embedding：TRANSPOSE → CONV_2D(16×16) → … → 加 CLS token → 加位置編碼 → [197,192]
[10–477]  Transformer block × 12（每個 39 個運算）
            LayerNorm(9) → FC(QKV) → 拆 Q/K/V → BMM(Q·Kᵀ) → MUL → SOFTMAX → BMM(×V) → 合併 → FC → ADD
            LayerNorm(9) → FC(192→768) → GELU → FC(768→192) → ADD
[478–488] LayerNorm(9) → STRIDED_SLICE（取 CLS）→ FC → [1,1000]
```

LayerNorm 被拆成 9 個整數運算：MEAN → SUB → MUL → MEAN → ADD(ε) → RSQRT → MUL → MUL(γ) → ADD(β)。

### LiteRT Micro 的執行流程（`main.cc`）

```text
GetModel(g_model)          解析嵌入的模型
RegisterDeitOps()          運算種類 → kernel 函式
AllocateTensors()          初始化（一次）
  ├ 規劃 arena 記憶體：生命週期不重疊的 tensor 共用空間 → 只用 1.09 MB
  └ 每個運算的 Prepare：讀離線參數表（requant 的 multiplier/shift、GELU 查表…）
Invoke()                   推論：for i = 0…488: kernel[i].Eval(輸入, 輸出)
比對 golden、印 RESULT
```

### 建置流程（`make`）

```text
① 電腦端（容器的 g++）：同一份 LiteRT Micro 以「記錄模式」編譯
     build/host/gen_offline_params 執行 AllocateTensors()
     → build/offline_params.bin（464 筆整數參數，186,780 bytes）
② RISC-V 端（riscv-none-elf-g++ -march=rv64imc）：以「重播模式」編譯
     main.cc + LiteRT Micro + GELU + bsp + data.S（.incbin 模型/圖片/golden/參數表）
     → build/deit.elf
③ spike --isa=rv64imc_zicsr_zicntr build/deit.elf
```

### 對 LiteRT Micro 做的修改

| 修改 | 原因 |
|---|---|
| 新增 GELU INT8 kernel（256 格查表）、resolver 加 `AddGelu` | LiteRT Micro 沒有 GELU |
| per-channel FC 的 requant 改單次四捨五入 | 與電腦版 LiteRT 一致，才能逐位元相同 |
| 離線參數表（`offline_params.{h,cc}` + 13 個 kernel 檔） | 初始化不做任何浮點（見 `docs/無浮點初始化說明.md`） |

## 5. 怎麼做到「只用整數」

| 階段 | 做法 |
|---|---|
| 模型 | 所有 tensor 是 INT8（bias INT32）。scale 只是附帶的說明資料，不拿來計算 |
| 推論 | `acc = Σ(x − zp)·w + bias`（int32）→ requant：`(acc × M) >> (31 − shift)` 四捨五入、加 zero-point、截斷。Softmax 用定點 exp，GELU 查表 |
| 初始化 | scale → M、shift 的換算在電腦上離線做，RISC-V 端只讀表 |
| 硬體 | `-march=rv64imc`：指令集沒有浮點指令；Spike 只開 `rv64imc_zicsr_zicntr` |

**W8A8 是資料格式，不是處理器**。處理器是一般的 RV64IMC（64 位元整數 + 乘除 + 壓縮指令，沒有 F/D/V）。INT8 資料用一般整數指令處理（`lb` 載入 1 個 byte、`mulw`、`addw`），一個 8 位元的數佔一整個 64 位元暫存器——這就是要加 packed MAC 指令的原因。

## 8. B0 數據（完整模型，實測）

| 項目 | 數值 |
|---|---:|
| 一次推論 | **12,617,761,175** 條指令 |
| 初始化 | 13,378,206 條 |
| MAC 數 | 1,253,683,200 |
| MAC / 指令 | 0.099（每個 MAC 約 10 條指令） |
| arena 記憶體 | 1,091,808 bytes |
| `.text` | 176,496 bytes |

### 各運算佔比（`make profile`）

| 運算 | 次數 | 佔比 |
|---|---:|---:|
| FULLY_CONNECTED | 49 | 67.3% |
| BATCH_MATMUL | 24 | 16.8% |
| SOFTMAX | 12 | 4.9% |
| CONV_2D | 1 | 4.1% |
| MEAN、MUL、ADD、SUB（LayerNorm、residual） | 237 | 6.5% |
| 其他 | 166 | 0.3% |

### 指令組成

整數 ALU 51.7%、load 24.7%、條件分支 11.8%、乘法 11.0%、store 0.5%。
load 平均每次只讀 2.11 bytes（`lb` 佔 load 的 81%）。

### 最熱的迴圈（`make analysis`）

- FC 內層迴圈：8 條/MAC × 10.46 億次 = **66.3%**（`lb ×2、addi ×2、addw（zero-point）、mulw、addw、bne`）
- BATCH_MATMUL 內層迴圈：11 條/MAC × 1.79 億次 = **15.6%**（多了兩邊 zero-point，且每圈從 stack 重讀 2 次）

### 前四大瓶頸

1. **純量、逐 byte 的乘加**：FC + BMM 兩個迴圈佔 81.9% → **packed INT8 MAC 指令**
2. **load 太多太窄**：每個 MAC 2.49 條 load、每次約 1 byte → 一次 `ld` 8 個 INT8 搭配 packed MAC
3. **迴圈與位址開銷**：FC 每圈 4 條在做指標、zero-point、迴圈判斷 → B1 軟體優化、之後可考慮 hardware loop
4. **requant**：FC 每個輸出迴圈外約 30 條；ADD 每元素 117 條、MUL 59 條 → **requant 指令**

（其他：Softmax 定點 exp 每輸出 443 條、MEAN 通用 reduce 很慢、Conv 輸入只有 3 通道迴圈太短 → 多為 B1 可處理）

## 9. 自己寫的 kernel（微基準，`src/`）

| 運算 | 檔案 | 整數做法 | B0 指令數 |
|---|---|---|---:|
| FC | `qfc_b0.c` | 三層迴圈，權重存 `[N][K]` | 每個 MAC 約 8.3 |
| Attention 矩陣乘法 | `matmul_b0.c` | 兩個輸入都有零點 | 每個 MAC 約 9.7 |
| Softmax | `softmax_b0.c` | 減最大值 → exp 查表 → 整數除法 | 每個輸出約 30 |
| LayerNorm | `layernorm_b0.c` | 整數平均、變異數、開根號，γ/β 定點 | 每個輸出 46.8 |
| GELU | `gelu_b0.c` | 256 項查表 | 每個輸出 7.0 |
| 殘差相加 | `add_b0.c` | 兩輸入各 requant → 相加 → 再 requant | 每個輸出 111.5 |

Requant（`requant.h`）的算法與 TFLite 相同：乘 quant_mult、除以 2³¹（四捨五入）→ 右移 shift → 加零點 → 截斷到 −128～127。

單層 FC（`qfc_b0`）的內層迴圈和 LiteRT Micro 的 FC 一樣是 8 條/MAC，所以新指令可以先在這裡驗證，再改到 LiteRT Micro 的 FC / BMM kernel。
